# Documentation and architecture decision records

Identify the decision, its audience and the implementation evidence. Inspect existing decision records for the project's location, numbering and headings. Follow that convention when the task calls for a new record.

Capture the status, context, constraints, decision, alternatives considered and consequences. Explain what made the selected option fit and what it costs. Keep proposed decisions visibly distinct from accepted ones. When a decision changes, link the superseding record so the earlier reasoning is still accessible.

For a documentation review, compare the specific claim with the current code, configuration or a reproducible check. Cite the relevant location. If the evidence is incomplete, record the open question. Keep examples and behavior claims consistent with what the evidence actually shows.
