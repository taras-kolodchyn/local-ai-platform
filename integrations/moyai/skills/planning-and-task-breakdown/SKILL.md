# Planning and task breakdown

Read the requirements and inspect the affected code. Identify dependencies, existing behavior and the evidence needed to accept the result. State assumptions that could change the plan.

Slice the change into small pieces that each deliver an observable behavior. Order prerequisites first and check the riskiest assumption early. For each step, name the affected component, a measurable acceptance criterion and the check that will demonstrate it.

For a planning request, present the plan in the conversation. When tracking implementation in Moyai, use its native plan and keep unfinished steps pending. Preserve work already in progress. Record open questions and update the plan when a check changes the evidence.
