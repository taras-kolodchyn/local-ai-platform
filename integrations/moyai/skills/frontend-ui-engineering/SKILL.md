# Frontend UI engineering

Start from the user's task, the project's existing components and the states the interface must represent. Define data ownership and state transitions for loading, empty results, success, validation failure and recovery. Prefer the existing component and spacing conventions.

For an interactive control, specify its accessible name, semantic role, keyboard action, focus transition and feedback. Check narrow and wide layouts, long content, reduced motion and visible focus. Preserve entered data when an action fails and make the next available action clear.

Deliver the component change or a design grounded in the supplied UI. Use existing local checks and supplied visual or accessibility captures. State which viewport and interaction checks have actually been observed.
